# inspection-station-v2 · 长沙输油站 · 站场巡检质量监督

`inspection-3d-sandbox` 的**布局与视角重排版**，不是重构。2.5D 平面图层、数据层、契约层、
`core` 的四个通用文件、`ui/cards.js` + `ui/itemlist.js` 与 `vendor` 全部用相对路径引用原目录
原文件，一行未改，也不复制副本 —— 两边读的是同一份字节，不会各自漂移。原目录保持可独立运行。

做法与 `poc/inspection-demo/hunan-overview-v2` 逐条对应（回字形、三档 token、卡片骨架、
状态色只染数字、`.num` 等宽、动效收敛、背景层砍到 2 层）。

本目录自己新写的：

```

styles/01-tokens.css            变量名单与原目录逐条一致（含 --cyan / --blue）；背景 6 层 → 2 层
styles/02-shell.css             回字形四行；顶栏三列 62px + 居中标题
styles/03-cards.css             card-metric / card-chart / st-table 三族

```

## 视角：监督者。第二个维度：时间

这是本屏与省域大屏的分工，也是这一版最关键的一条：

| | 数据形状 | 图表横轴 | 回答 |
| --- | --- | --- | --- |
| `hunan-overview-v2`（省域） | 141 个站点 × 一个时点 | 作业区 | 哪个作业区差 |
| `inspection-station-v2`（本屏） | 1 个站点 × 14 个时点 | **巡检轮次** | 这个站最近怎么样、在变好还是变差 |

同一个指标在两屏换的是**轴**，不是 scope。

这也解开了单站单轮上「完成率恒 100%」那个死结：256 条巡检项每轮都提交完（数据模型的
真实边界，见原目录 `scripts/data/series.js` 的注释），所以「提交完成率」在单轮上恒等于 1。
监督者真正要问的不是「勾打完了吗」，而是**「打完的这些勾里有多少是走过场的」** —— 于是有了
**合规率**：提交项里扣掉被三类行为异常判定为无效的那些。

左栏三张图连起来就是一句话：**越赶越糙**。

```
用时     88 92 85 79 90 74 78 83 70 72 68 66 64 63   分钟（14 轮）
合规率 98.8 …………………………………………………… 94.9 95.3   %
行为异常  3 ……………………………………………………… 13  12   次
```

**四边分工**：上带 + 左栏恒为**全站**基准、下钻时**逐字不变**（`verify_station.py` 对这条有
可执行断言）；跟随焦点变的只有三处 —— 平面图高亮、右栏、区域带高亮。点开储油罐区时全站的
合规率曲线仍在屏上，可以和右栏该区的明细对读。

**上带每个大数都带一行 note**（「较上轮 −1 次」这类）。这和 `hunan-overview-v2` 那边「一律
不传 note」是相反的做法：省域没有时间维，那边的 note 只能重复绝对值，所以要删；这里副行
装的是趋势对比，正是这一屏比一个静态数字多出来的信息。

## 新增数据：`scripts/data/quality.js`

原目录数据层有 256 条真实巡检项、12 区台账、真实轨迹、任务卡的计划/实际时段，但**没有任何
质量监督维度的字段**。这份数据补上，与
`hunan-inspection-overview/scripts/data/quality.js` 是同一类产物（手写的演示数据表）。

**最后一轮就是本页地图与巡检项列表展示的那一轮**，它的四个字段全部从真实数据现算并在
`assertAnchor()` 里逐条断言：

| 字段 | 值 | 真源 |
| --- | --- | --- |
| `planned` | 256 | `Map3DContract.TOTAL_ITEMS`（12 区真实项数求和） |
| `issues` | 3 | `DemoStation.stationProgress().issueCount` |
| `p1` | 2 | 256 条项里 `status === "danger"` 的条数 |
| `minutes` | 63 | `DemoTrack.track().durationMin` |
| `date` | 2026-08-04 | `DemoTask.task().actualStart` 的日期 |

改动 `items-*.js` 里任何一项的 status，或改 track 的时长，启动时直接抛错 —— 不会静默漂移成
「趋势图的最右点和屏上这一轮对不上」。前 13 轮是演示数据。

**本轮 18 条明细**（12 条行为异常 + 6 条 AI 提醒）每条挂一个**真实巡检项**：`itemIndex` 是该区
`DemoItems[areaId]` 的下标，运行时取出真实的 `point`/`title`。逐类条数必须等于最后一轮的
对应字段，由 `assertDetails()` 强制。

### 三类行为异常的判定对象改成「项」

省域那份 `quality.js` 的口径是「<10min / <10s / 偏移30min」，那是对**一次巡检任务**的判定。
站点这一层的最小单位是 256 个巡检项，所以判定对象换成项：

| | 阈值 | 本轮 |
| --- | --- | --- |
| 时长异常 | 单项现场停留 < 10 秒 | 6 |
| 间隔异常 | 相邻两项提交间隔 < 3 秒 | 4 |
| 时段异常 | 提交时刻偏离计划时段 30 分钟以上（与省域一致） | 2 |

改口径不是拍脑袋：真实轨迹是 **63 分钟走完 256 项 = 平均 14.8 秒/项**，所以「有些项停留不足
10 秒」在这份数据里本来就可信；反过来若沿用「任务用时 <10min」，本站一轮 63 分钟永远不会
触发，那条指标恒为 0。

### 跨屏不对齐是明确决定

本站属长沙作业区，而省域那份 `quality.js` 里长沙作业区 `issues=1`、需关注站点是「8#阀室」。
两屏刻意各自自洽、不做数字对齐（2026-08-23 决定）。本文件不引用省域那一侧的任何数字。

## 顺手修掉的一个既有 bug（改了共享的 engine.js）

⚠️ 这次改动落在原目录 `scripts/map3d/engine.js`，两个页面共享。

**症状**：点任何区域下钻，控制台抛 `TypeError: Cannot read properties of undefined (reading 'clone')`，
3D 选中高亮完全不生效，之后每次切区再抛一次。原目录 `index.html` 同样中招（已对照验证），
不是本次重排引入的。

**根因**：四个 tank 区的罐号铭牌（`model-plan.js` 的 `buildNameplateTexture` +
`MeshBasicMaterial`，经 `addPart` 落进 `areaMeshes[areaId]`）用的是**不受光照的材质，没有
`emissive` 属性**，而 `cacheAndApplySelection` 对区域内每个材质都要 `material.emissive.clone()`。
更糟的是 `setActiveAreaHighlight` 在调用它**之前**就已经把 `engine.activeAreaId` 写成了目标
区域 —— 于是 `selectionCache[id]` 永远没建立，此后每次切区都会在 `restoreSelection` 的
`cache.forEach` 上再抛一次，级联成 12 个区全部无法选中。页面其余部分照常渲染，所以一直没被
发现。

**修法**：新增 `highlightableMaterials(mesh)`，只把带 `emissive` 通道的材质纳入选中高亮。
这不是容错兜底 —— 不发光的材质本来就没有「发光强度」可以调，排除它是语义正确。
`verify_station.py` 里有专门的回归断言（**逐 12 个区**跑一遍 `setActiveArea`，只测一个测不出级联）。

## 跑验收

```sh
cd /Users/admin/Code/xunjian-ai-demo
find poc/inspection-demo/inspection-station-v2 -name '*.js' -print0 | xargs -0 -n1 node --check

```

预期 `ALL CHECKS PASSED（68 项断言）`，截图落到 `$TMPDIR/inspection-station-v2-verify/`
（可用 `SHOT_DIR=` 覆盖）。六组断言：

| 组 | 防的是什么 |
| --- | --- |
| A 加载健康 | pageerror / console.error 白名单外 / WebGL 上下文单例 |
| B 回字形骨架 | 四行五区、各区块数、旧结构类名不存在、已删文案检索不到、图表槽位 |
| C 3D 契约 | host 唯一、12 热点数与顺序 === `AREA_IDS`、`assertPinNamespace`、**热点两两不重叠**、**逐区高亮不抛错**、渲染预算 |
| D 质量数据自洽 | 最后一轮四字段等于真实现算值、合规率派生、明细逐类条数、明细表行列 |
| E 焦点跟随 | 下钻后上带与左栏**逐字不变**；两个下钻入口 + 两条返回路径 |
| F 按需渲染 | 复位后静置 900ms 不再出帧 |

实测：全景态 `renderCalls=175 triangles=35932`；平面图容器 1303 × 925 设计像素。

⚠️ C 组那两条是成立条件，不是普通断言。**热点不重叠**：回字形上下各让掉一条带，中段变矮，
而 2.5D 用固定角度透视相机 —— 容器变矮就是整张图等比缩小、热点投影间距同步缩小；
`05-map3d.css` 是禁改区，`sweepLabels` 不是收敛循环（写成 `while(changed)` 会因浮点误差
死锁整页），一趟推不开就是推不开。这一项红了，退路是 ① 压薄 `.st-area-band`（132 → 100）
把高度还给平面图 ② 还不够就退回三栏。**不要改 3D 机位。**

`wait_idle()` 只轮询 `idle`、**不**在等待里复核「frames 不再涨」：`debugInfo().idle` 就是
`!engine.dirty` 一个标志，而区域选中态的热点脉冲会周期性重新置脏，frames 每隔一会儿 +1 是
按需渲染的正确行为。「停下来真的不再画」由 F 组单独验（先清选中态让脉冲停）。

验收脚本用 Python Playwright（本仓库 `.venv` 里有，与
`poc/inspection-demo/diagnosis-flow/verify/verify_flow.py` 同一条路），不是原目录那份 Node 版
—— Node 的 playwright 在开发机上只能从 npx 缓存目录解析，不可移植。
