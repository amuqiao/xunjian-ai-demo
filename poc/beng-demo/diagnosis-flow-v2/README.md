## 二、★ 故事线：`泵课题Q&A.docx` 的四步在屏上都指得到

那份文档的故事线是「时序引擎 → 视觉引擎 → RAG 引擎 → 应用层」。**依据链按这四步分段**，
每段带小标题，讲解时逐段往下指：

| 故事线 | 依据链段 | 屏上内容 |
|---|---|---|
| 时序引擎检测异常 | **① 时序引擎** 2 枚 | 曲线 16:30→16:37 末点 11.9 全程 ISO D 档；**真 SCADA 截图**（标题/量程可逐字核对）|
| 视觉引擎排除误报 | **② 视觉与实测** 2 枚 | 激光对中实测 H 向 0.31→−0.02mm；渗漏排除（库内典型形态对照）|
| RAG 检索 Top-N 生成诊断 | **③ 检索与判定** 2 枚 | Top-4 检索表（相似度 + 确诊）+ 置信度加权四项；ISO 判定口径 |
| 应用层生成工单/备件/作业卡 | **④ 应用层** 1 枚 | 分级处置：立即 / 4h / 24h / 72h |

**诊断名在表上和 AI 判断卡最显眼处都有**：记录表第一行写着
`疑似 轴承磨损 / 润滑不良 83%`，AI 判断卡第一行也是它，「建议处置」降到下面一档。
第一版最显眼的位置放的是处置动作（「确认异常，转分级处置」），讲到"生成诊断报告"
那一步时屏上指不到诊断名 —— 那是缺口，已补。

### 三处刻意不照抄原文

1. **诊断名用「轴承磨损 / 润滑不良」，不用原文的「轴承内圈剥落」**。后者是那份 Q&A 编的
   （同段的 `CASE-2023-0417` / `XX站` / `YY厂` / `2号泵` 也都是编的）。本版措辞取自
   **Top-2 衡阳 P-2 的 2026-06 在线监测报告原文** —— 同站、同型号 200DY390-HY、
   形态最接近的那一条真实确诊。被追问"这诊断哪来的"时点开 Top-4 表就能答。
2. **置信度 83% 而不是 87%**：83 是四项加权真乘出来的（见下），87 是原文写的。
3. **备选诊断换了**：原文是「联轴器对中不良 65%」（依据轴向位移 0.08mm），本版是
   「低流量长期偏离优先工作区 61%」（依据 Top-1 长岭 P-01 的真实确诊根因）。
   ⚠️ 原因是**素材把原文那个备选直接排除了**：Easy-Laser 实测 H 向 0.31→−0.02mm 已合格，
   而同时段振动没降。它已经不是"未排除的备选"，而是"被排除的分支"。原文让它留在 65%，
   是因为那边只有"视觉说没看出偏移"这种弱证据；而原文用来支撑备选的轴向位移 0.08mm，
   本机组没有这个测点。
   **要改回原文口径，必须连第 2 条记录（对中已合格 94%）与 ② 段那枚实测证据一起改**，
   只改备选会当场自相矛盾。

## 三、置信度可被追问：83% = 四项相乘

Q&A 的 Q1 就是「这数字怎么算出来的，别编个数据糊弄我」。屏上（③段那枚「历史案例 Top-4」）
把四项摊开，每项都有对应证据：

| 项 | 值 | 依据 |
|---|---|---|
| 时序特征匹配 | 0.86 | 持续 7 分钟高位 + 峰群，与 Top-1/Top-2 形态接近 |
| 对中已排除 | **+1.08** | 实测 0.31→−0.02mm 合格而振动未降 |
| 同型号同站加权 | **+1.05** | Top-2 是同站同型号 200DY390-HY |
| 确诊标签分布 | **0.85（减分）** | Top-4 里只有 2 条确诊为机械类 |

`0.86 × 1.08 × 1.05 × 0.85 ≈ 0.83`。**减分项和加分项一样显眼**，藏起来等于糊弄那个追问。
`domain/04-records.js` 里有 `assertConfidence()` 钉死这件事：谁改了任一项，加载即炸，
不会出现"四项相乘 0.72、卡上写 83%"。

## 四、Top-4 检索：四条真报告，确诊各不相同

这是全屏最有说服力的一块 —— 原文想讲「Top-5 里第 3 条确诊是别的原因」，而真实资料里
**四条的确诊没有一条相同**，其中两条的机泵本体完全没问题：

| # | 案例 | 相似度 | 真实确诊 |
|---|---|---|---|
| 1 | 长岭站 P-01（2025-03-26）| 0.88 | 低流量长期偏离 API 610 优先工作区（额定 900，实际 575）|
| 2 | 衡阳站 P-2（2025 评估 → 2026-06 监测）| 0.81 | 轴承磨损、润滑不良（评估 A 优一年后判故障）|
| 3 | 汨罗站 P-02（2025-06-12）| 0.76 | **振动探头故障**（0.282 突变 14.2，换探头即正常）|
| 4 | 长岭站 B-02（2025-04-29）| 0.72 | **工艺操作水击**（停泵前未按规程节压至 80%）|

「振动高 ≠ 轴承坏」这句话不用讲，指着表就说完了。

### 一处如实标注的能力边界

Q&A 故事线第二步是「视觉引擎确认泵体无渗漏」。**本轮素材里没有一张泵体近景照片**
（五张的主体是 SCADA 界面、仪器屏幕、人和仪器）。所以那枚证据做成「库内典型形态 +
明说这一项是谁判的」：结论行写明**渗漏排除依据是机械专业岗现场目视确认，不是视觉模型判定**。

编一张图、或把现场作业照当泵体近景框起来，都是在这一步造假 —— 而这一步恰恰是 Q&A 里
专家最爱追问的地方（Q3「它的检测精度到底是多少」）。

### 一处读图读错后的修正

SCADA 截图顶部那行 `9.5 / 9.8` 起初被我当成了本曲线的报警/停机阈值。它其实在画面里
**另一个表格**（同列下方还有 `90 / 95`），而且曲线图例文字是「温度」——SCADA 组态没跟着
标题改。改用 **ISO 10186-3**（与 `pump-station-situation-v2` 同一套口径，三屏一致）：
A<2.3 / B 2.3~4.5 / C 4.5~7.1 / D≥7.1，曲线 8.2~12.1 **全程落在 D 档**。
那枚识别框没删，反而留着并标注「非本测点」—— 路演时一定有人指着它问，不如自己先讲清楚。

## 七、备件与作业卡：只有文字说明，不做假动作

按需求，故事线第四步的「IMS 工单 + 推送备件信息 + 移动端作业卡」**全部是文字说明**。
两处落点：

- ④ 段那枚「分级处置建议」的最后一行（虚线框 + muted）
- **归档浮窗的「处置去向」**四行：IMS 工单（待人工开单）/ 备件清单（待人工核对）/
  移动端作业卡（**未接入**）/ 下轮复查（待排期）

三条硬约束，验收里一起验：**0 个可点元素**、不出现「已推送 / 已生成 / 已发送 / 已开单」、
明写「未接入」。四行状态一律是未完成态 —— 做一个假的"已推送"，是这类演示最容易被
当场问穿的地方。

## 八、报告：屏上所见 = 下载所得

九段（含一段仅分歧态出现），章节编号**派生**不写死：

```
AI 诊断结论 / 一、基础信息 / 二、多源证据摘要 / 三、置信度构成 / 四、分级处置建议 /
五、人工复核意见 / [六、复核分歧说明] / 归档标签 / 六(七)、附件来源
```

比参照物多「置信度构成」与「分级处置建议」两段 —— Q&A 里被追问过的东西必须落到纸上，
而不是只印一个 83%。两份预构建 PDF 按分歧态取：

```sh
uv run python poc/beng-demo/diagnosis-flow-v2/tools/build_report.py
```

改判版刻意采纳**备选诊断**（先核工况、暂不停机），不是随便换一个结论 —— 那才是 Q&A 里
专家真正在争的那件事。
