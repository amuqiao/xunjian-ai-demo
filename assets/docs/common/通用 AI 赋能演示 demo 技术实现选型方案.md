
# 通用 AI 赋能演示 demo 技术实现选型方案

本文用于把“AI 赋能项目”的演示诉求，收口成可复用、可稳定展示、可讲清边界的 demo 技术实现方案。

它不绑定具体业务流程，不用于正式系统建设。本文默认边界是：**仅演示效果，不接入真实模型，不训练真实视觉模型或时序模型，不对接真实生产系统，不构成正式业务判断依据**。

## 0. 结论速览

通用 AI 赋能演示 demo 推荐采用 `可交互模拟 demo`：

```text
固定 demo 数据集
  + 预置识别 / 分析结果
  + 规则 / 模板 / 脚本化 AI 效果
  + 可视化证据链
  + 限定意图对话
  + 页面态报告
  + 本地可复现演示
```

第一版要证明的不是“模型真的上线了”，而是：

```text
AI 能如何进入某类业务场景，
把原始数据、记录、图片、文档或事件，
转化为识别、分析、解释、建议、摘要、报告和可追溯结论。
```

推荐第一版做成这些演示态能力：

| 能力 | 第一版实现深度 |
| --- | --- |
| 场景总览 | 用固定 demo 数据展示关键指标、风险、待办、摘要或成果。 |
| AI 识别效果 | 使用预置识别结果、标签、置信度、证据框或结构化字段展示识别后的业务价值。 |
| AI 分析效果 | 使用规则、统计口径或脚本化计算生成等级、分类、排序和建议。 |
| AI 解释效果 | 使用模板生成解释文本，说明命中依据、证据来源和建议动作。 |
| 对话查询 | 限定 3-5 个演示意图，返回固定数据驱动的回答。 |
| 报告输出 | 生成页面态报告、摘要卡片或固定模板文档预览。 |
| 演示闭环 | 展示状态变化、处理建议和结果沉淀，但不触发真实流程。 |

第一版明确不做的事情：

| 不建议第一版默认做 | 原因 |
| --- | --- |
| 接入外部或自建模型服务 | 本文定位是演示效果，不验证模型能力或部署能力。 |
| 训练、微调或评测模型 | 会把 demo 变成算法项目，需要样本、标注、算力和评测体系。 |
| 对接真实生产系统 | 接口、权限、网络、数据脱敏和联调会改变 demo 性质。 |
| 开放式万能 Agent | 演示不可控，现场问题容易超出已准备的数据和逻辑。 |
| 自动执行真实审批、派单、通知或写回 | 涉及权限、责任和审计，不适合作为演示默认能力。 |
| 承诺真实环境指标 | 演示数据不能代表真实生产环境。 |

一句话红线：

```text
本方案仅用于演示 AI 赋能效果，当前结论基于样例数据、预置结果和演示编排生成，
不构成真实模型推理、真实系统接入或正式业务决策依据。
```

## 1. 文档适用范围

本文适用于这些场景：

| 场景 | 使用方式 |
| --- | --- |
| 售前演示 | 快速说明 AI 能力如何嵌入某类业务场景。 |
| 大赛 / 汇报 demo | 用完整故事线展示 AI 提效、分析和报告能力。 |
| 立项前原型 | 帮助业务方理解未来系统可能长什么样、解决什么问题。 |
| 内部创新展示 | 在不接真实系统的情况下展示 AI 赋能方向。 |
| 多项目复用 | 替换业务对象、数据样例和演示脚本即可复用。 |

本文不适用于这些场景：

| 不适用 | 应另行处理 |
| --- | --- |
| 正式系统建设方案 | 需要真实架构、接口、权限、数据治理、运维和验收设计。 |
| 算法验证方案 | 需要样本、标注、训练、评测、模型版本和指标体系。 |
| 真实系统集成方案 | 需要接口文档、网络环境、账号权限、联调计划和错误处理设计。 |
| 合规审计方案 | 需要数据分类分级、授权、留痕、脱敏、审计和责任边界。 |

## 2. 核心心智模型

通用 AI 赋能 demo 不应从“用什么模型”开始，而应先确认它要演示哪一种 AI 价值。

```text
输入层
  文本 / 表格 / 图片 / 文件 / 事件 / 记录 / 指标 / 历史样例

AI 效果层
  识别 / 分类 / 抽取 / 分析 / 预测感 / 解释 / 摘要 / 生成 / 问答

业务表达层
  风险 / 异常 / 质量 / 效率 / 建议 / 报告 / 待办 / 复核 / 归档

演示输出层
  看板 / 详情页 / 证据链 / 对话框 / 报告页 / 状态流转 / 导出预览
```

第一版 demo 的关键不是功能多，而是让观众清楚看到：

```text
原始材料进入系统
  -> 系统产生 AI 风格的分析结果
  -> 每个结论都有证据和解释
  -> 用户可以追问、查看、确认或生成报告
  -> 结果沉淀为可复用的管理输出
```

## 3. 演示边界

第一版必须明确以下边界，避免被误解为正式项目。

| 边界项 | 第一版推荐 | 不建议承诺 |
| --- | --- | --- |
| 数据来源 | 固定 demo 数据集、Mock API、离线 JSON / CSV / 图片样例 | 真实系统实时数据。 |
| 模型能力 | 预置结果、规则计算、模板生成、脚本化效果 | 真实模型推理、训练、微调、在线评测。 |
| 对话能力 | 限定意图、固定问题池、基于 demo 数据回答 | 回答任意开放问题。 |
| 识别能力 | 展示已准备好的识别框、标签、字段、置信度 | 对任意图片、视频、文件通用识别。 |
| 分析能力 | 对冻结样例做规则、分类、排序、摘要 | 对真实业务数据做生产级判断。 |
| 操作闭环 | demo 内状态流转、处理建议、报告生成 | 写回真实系统、触发真实工单或通知。 |
| 责任边界 | 用于演示和辅助理解 | 作为正式决策、考核、审批或审计依据。 |

推荐在文档、页面或讲解中保持一句话口径：

```text
本 demo 用固定样例演示 AI 赋能效果，所有识别、分析和生成结果均用于展示，不代表正式系统能力。
```

## 4. 推荐演示分层

### 4.1 交互展示层

负责让观众快速理解 demo 在解决什么问题。

推荐页面：

| 页面 | 作用 |
| --- | --- |
| 首页总览 | 展示核心指标、AI 摘要、异常数量、待处理项和演示入口。 |
| 场景详情 | 展示某个业务对象、记录、图片、文档或事件的完整分析过程。 |
| AI 证据页 | 展示命中规则、识别结果、来源数据、截图、字段或文本片段。 |
| 对话查询 | 支持固定问题或限定意图输入，展示 AI 助手感。 |
| 报告摘要 | 展示模板生成的周报、日报、分析结论或复盘摘要。 |
| 配置说明 | 可选展示规则、样例数据和可扩展能力，不做复杂后台。 |

### 4.2 演示编排层

负责控制故事线，确保现场演示稳定。

推荐实现：

```text
演示脚本
  -> 固定 demo 数据集
  -> 固定页面路径
  -> 固定查询意图
  -> 固定异常样例
  -> 固定报告模板
```

需要提前冻结：

| 冻结项 | 内容 |
| --- | --- |
| 演示故事 | 观众要看到哪条 AI 赋能主线。 |
| 样例数据 | 正常样例、异常样例、对比样例、报告样例。 |
| 页面路径 | 从首页到详情、证据、对话、报告的点击顺序。 |
| 问题池 | 允许现场输入或点击的 3-5 个问题。 |
| 展示口径 | 哪些是已实现演示效果，哪些是未来可扩展方向。 |

### 4.3 规则与效果层

负责生成“像 AI 一样分析”的可解释结果。

推荐能力：

| 能力 | 实现方式 |
| --- | --- |
| 分类 | 根据字段、标签或规则把记录分成正常、关注、异常、高风险等。 |
| 评分 | 用权重、扣分项或分级规则生成质量分、风险分、优先级。 |
| 排序 | 按风险等级、时间、重要性或命中规则数量排序。 |
| 解释 | 用模板说明“为什么系统这样判断”。 |
| 建议 | 根据结论类型匹配建议动作或复核清单。 |
| 摘要 | 将结构化结果拼装为自然语言报告段落。 |

这些能力可以按样例数据计算，但不应包装成真实模型推理。

### 4.4 数据与证据层

负责让结果可追溯。

推荐数据对象：

| 对象 | 示例字段 |
| --- | --- |
| `DemoScenario` | 场景名称、演示目标、入口页面、脚本步骤。 |
| `DemoEntity` | 业务对象名称、类型、状态、重要性、标签。 |
| `DemoRecord` | 时间、来源、字段、原始值、处理状态。 |
| `DemoEvidence` | 证据类型、证据内容、截图路径、字段路径、命中规则。 |
| `DemoRule` | 规则名称、触发条件、展示文案、等级映射。 |
| `DemoInsight` | 结论类型、等级、摘要、原因、建议、关联证据。 |
| `DemoReport` | 报告类型、生成时间、摘要、结论列表、后续动作。 |

关键要求：

- 每个演示结论至少能回到一条样例数据或一条规则。
- 缺失样例不要静默补齐，应在演示准备阶段修正数据。
- 页面展示的结论、对话回答和报告摘要应来自同一份 demo 数据。

## 5. 可选实现参考

具体技术栈只作为实现参考，不代表正式系统架构。通用 demo 应优先稳住演示边界、故事线和样例数据，再按团队习惯选择实现方式。

### 5.1 纯前端演示

适用：时间短，只需要稳定展示和少量交互。

| 层 | 推荐技术 | 说明 |
| --- | --- | --- |
| 前端 | `React + Vite + TypeScript` | 开发快，适合可交互 demo。 |
| UI | `Ant Design` / `shadcn/ui` / 项目既有组件 | 优先沿用团队熟悉方案。 |
| 图表 | `ECharts` / `Recharts` | 展示趋势、分类、占比、排名。 |
| 数据 | 本地 `JSON` / `CSV` / 静态资源 | 不需要服务端即可运行。 |
| 状态 | 前端状态管理或页面内状态 | 控制演示流程、筛选和状态变化。 |
| 部署 | 静态站点或本地构建产物 | 适合离线演示。 |

推荐用于：

- 大屏、汇报、比赛、初次沟通。
- 不需要复杂导出、登录或后端计算的 demo。
- 数据和演示路径完全固定的项目。

### 5.2 前端 + 轻量后端演示

适用：需要更强交互、报告生成、文件预览或本地数据处理。

| 层 | 推荐技术 | 说明 |
| --- | --- | --- |
| 前端 | `React + Vite + TypeScript` | 工作台、详情页、对话页、报告页。 |
| 后端 | `FastAPI` / `Node.js` | 提供 Mock API、规则计算、报告拼装。 |
| 存储 | `SQLite` / 本地 JSON 文件 | 演示数据量小，方便迁移。 |
| 文件 | 本地目录 | 存图片、报告模板、截图、附件样例。 |
| 部署 | 本地脚本或 `Docker Compose` | 适合单机稳定演示。 |

推荐用于：

- 需要导出或生成报告预览。
- 需要模拟状态流转。
- 需要把 Mock API、规则计算和模板拼装从页面代码中拆出来。

### 5.3 默认推荐

如果没有特别限制，推荐：

```text
React + Vite + TypeScript
  + 本地 JSON demo 数据
  + 前端规则计算
  + ECharts 图表
  + 固定意图对话
  + 静态构建部署
```

只有在需要报告文件生成、复杂数据处理或本地文件预览时，再增加轻量后端。

## 6. AI 效果如何模拟

### 6.1 识别类效果

适用于图片、截图、票据、表单、文档、设备、场景或质量检查。

推荐做法：

```text
样例图片 / 文档
  -> 预置识别框、标签、字段、置信度
  -> 页面展示高亮区域
  -> 生成结构化结果
  -> 关联后续分析和建议
```

不要写成：

```text
系统已具备通用视觉识别能力
```

建议写成：

```text
demo 使用预置识别结果演示 AI 识别后的业务效果。
```

### 6.2 分析类效果

适用于风险判断、质量评分、异常发现、优先级排序和趋势展示。

推荐做法：

```text
样例记录 / 指标 / 事件
  -> 规则计算
  -> 等级映射
  -> 命中原因
  -> 建议动作
  -> 证据链展示
```

不要写成：

```text
系统通过真实时序模型预测异常。
```

建议写成：

```text
demo 使用固定样例和规则口径模拟趋势研判效果。
```

### 6.3 生成类效果

适用于摘要、报告、建议、复盘、说明和对话回答。

推荐做法：

```text
结构化结论
  -> 文案模板
  -> 可变字段填充
  -> 生成摘要 / 建议 / 报告段落
```

不要写成：

```text
系统调用大模型自动生成专业报告。
```

建议写成：

```text
demo 使用模板化生成方式展示 AI 报告助手效果。
```

### 6.4 对话类效果

适用于“AI 助手感”的现场演示。

推荐支持 3-5 个限定意图：

| 意图 | 示例 |
| --- | --- |
| 查询异常 | “今天有哪些异常？” |
| 查询原因 | “为什么这个对象被标红？” |
| 查询建议 | “下一步应该怎么处理？” |
| 生成摘要 | “生成本次分析摘要。” |
| 查看证据 | “这个结论依据是什么？” |

推荐流程：

```text
用户问题
  -> 意图匹配
  -> 参数匹配
  -> 查询 demo 数据
  -> 组装证据
  -> 模板回答
```

边界：

- 不承诺开放问答。
- 不允许对话修改真实数据。
- 回答必须基于 demo 数据和预置规则。

## 7. 通用演示故事结构

每个项目复用本文时，只需要替换业务对象、样例数据和页面文案。

推荐故事线：

```text
1. 首页看到整体态势
2. 某个对象或事件被 AI 标记
3. 进入详情查看识别 / 分析结果
4. 查看命中规则和证据链
5. 系统给出解释和建议
6. 用户通过对话追问
7. 系统生成摘要或报告
8. demo 内状态完成一次模拟流转
```

通用页面结构：

| 页面 | 必须展示 |
| --- | --- |
| 总览页 | 指标、异常、AI 摘要、入口。 |
| 列表页 | 对象、状态、等级、更新时间、建议动作。 |
| 详情页 | 原始数据、AI 结果、证据、解释。 |
| 对话页 | 固定意图问答、证据引用、摘要生成。 |
| 报告页 | 自动摘要、关键结论、建议清单。 |

## 8. 可复用模块清单

### 8.1 必做模块

| 模块 | 作用 | 实现建议 |
| --- | --- | --- |
| Demo 数据集 | 支撑所有页面和对话 | 本地 JSON，字段稳定。 |
| 总览看板 | 建立第一眼价值 | 指标卡、图表、AI 摘要。 |
| 详情分析 | 展示 AI 如何判断 | 原始数据 + 结论 + 证据。 |
| 规则解释 | 避免结果像纯文案 | 命中条件、等级、原因。 |
| 限定对话 | 增强 AI 感 | 固定意图 + 模板回答。 |
| 报告摘要 | 展示管理输出 | 模板生成页面态报告。 |

### 8.2 可选模块

| 模块 | 适用情况 | 注意 |
| --- | --- | --- |
| 状态流转 | 需要演示闭环 | 只在 demo 内流转。 |
| 文件上传假入口 | 需要模拟导入材料 | 上传后读取预置结果，不做真实解析。 |
| 图像标注展示 | 需要视觉效果 | 使用预置框和标签。 |
| 时间线 | 需要展示过程 | 用固定事件序列。 |
| 知识库命中 | 需要展示依据 | 使用少量本地条目。 |
| 报告导出预览 | 需要汇报感 | 可先做页面预览，不一定生成真实文件。 |

## 10. 页面表达原则

### 10.1 首页

首页不要做成营销页，应直接进入可操作的演示工作台。

推荐首屏包含：

- 核心指标。
- AI 摘要。
- 异常或重点对象列表。
- 趋势或分布图。
- 进入主场景的操作入口。

### 10.2 详情页

详情页要把“结论”和“依据”放在一起。

推荐布局：

```text
对象基本信息
  -> AI 结论
  -> 关键证据
  -> 命中规则
  -> 建议动作
  -> 相关记录
```

### 10.3 对话页

对话页不应单独存在，而应能引用当前场景数据。

推荐：

- 提供 3-5 个快捷问题。
- 支持输入固定问题。
- 回答中展示引用证据。
- 对无法覆盖的问题给出明确提示，不编造答案。

### 10.4 报告页

报告页应展示“AI 帮忙总结”的效果。

推荐包含：

- 一句话摘要。
- 关键发现。
- 风险或问题清单。
- 建议动作。
- 证据附件或引用。
- 生成时间和 demo 数据版本。

## 13. 验证清单

完成前至少检查：

- 所有页面能按演示脚本走通。
- 首页、详情、对话、报告使用同一份 demo 数据。
- 每个结论都有证据或规则依据。
- 对话问题池覆盖现场要问的问题。
- 页面没有写成真实模型、真实系统或生产能力。
- 断网、本地环境或会议室环境下仍可演示。
- 不存在临场手工改数据、改页面、改回答才能跑通的步骤。
