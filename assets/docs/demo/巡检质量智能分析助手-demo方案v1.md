# 巡检质量智能分析助手 demo 方案 v1

> 面向业务方确认使用。  
> 本文用于确认 demo 骨架、演示故事、视觉模型介入点、时序模型介入点，以及业务方需要拍板的优先级和素材。

## 1. Demo 定位

本 demo 不是重做巡检系统，也不是正式项目交付版本。

它要证明一件事：

```text
在现有“定期巡检 -> 填写表单 -> 到位监控 -> 异常复检 -> 报告归档”流程不变的前提下，
AI 可以辅助发现疑点、给出复检依据、生成巡检报告，
让巡检工作从“人工记录和事后核查”变成“AI 提醒、人工确认、经验沉淀”。
```

首版 demo 的重点不是功能多，而是用一条能讲清楚的业务故事体现 AI 赋能价值。

## 2. Demo 主骨架

推荐 demo 按下面骨架设计：

```text
巡检任务
  -> 巡检表单
  -> AI 发现疑点
  -> 知识库给出依据
  -> Agent 辅助复检
  -> 人工确认
  -> Agent 生成报告
  -> 归档复用
```

这条骨架嵌入现有业务流程，不改变巡检人员的基本工作方式。

| 现有业务动作 | demo 新增辅助 | 人工仍需确认 | 本步输出 | 主要使用人 |
| --- | --- | --- | --- | --- |
| 定期巡检 | 展示巡检任务、计划时间、实际时间、巡检区域 | 本次巡检是否按实际业务路线展示 | 巡检任务卡、到位疑点 | 运维人员、管理人员 |
| 填写表单 | 对少量检查项给出 AI 提醒，例如趋势异常、图片识别结果、漏填提示 | 现场状态是否属实，表单是否需要修正 | 被标红的表单项 | 运维人员 |
| 到位监控 | 标记迟到、巡检时长异常、报警后仍填正常等疑点 | 是否存在合理原因 | 到位/履职疑点 | 管理人员 |
| 异常复检 | 自动生成复检清单，提示需要复核的点和补拍证据 | 是否发起复检，复检结论是什么 | 复检清单、人工确认结果 | 复检人员、班组长 |
| 报告归档 | 自动生成巡检摘要、异常摘要、交接班关注项 | 报告内容是否确认归档 | 巡检报告、案例摘要 | 管理人员、交接班人员 |

## 3. AI 介入点总览

AI 不需要覆盖全部巡检工作。首版只选 1 条主线能力做扎实，视觉识别只作为同一主故事里的加演增强，不作为默认主线。

| 能力 | 在 demo 中的作用 | 首版建议 |
| --- | --- | --- |
| 时序预警 | 从压力、差压、液位、温度等连续数据中发现趋势异常 | 推荐作为默认主线。 |
| 视觉识别 | 从现场图片中识别指示灯、表计、阀位等可见状态 | 作为同一主故事的加演增强；后续可再评估视觉优先故事。 |
| 规则质检 | 判断迟到、漏填、异常未说明、报警后仍填正常 | 必做，但只做少量规则。 |
| 知识库 | 命中巡检标准、阈值依据、复检步骤、案例摘要 | 必做，这是参赛赛道重点。 |
| Agent | 生成复检清单、巡检摘要、交接班关注项 | 必做，但限定在巡检场景内。 |

## 4. 视觉模型适合辅助的检查项

视觉模型适合处理“看得见、能拍照、能判断状态”的巡检项。首版不承诺全量视觉巡检，只选 1 个代表项展示效果。

### 首版可选项

| 视觉检查项 | 对应业务价值 | demo 展示方式 | 建议 |
| --- | --- | --- | --- |
| 电动执行机构指示灯 / 面板状态 | 辅助判断现场状态是否正常，减少人工逐项盯屏和填表 | 展示识别框、状态标签、置信度，自动标红表单项 | 首版推荐 |
| 压力表 / 液位计读数 | 辅助读取仪表数值，减少人工抄录错误 | 展示读数区域和识别数值，辅助回填表单 | 可替换 |
| 阀位 / 开关状态 | 判断现场状态与表单填写是否一致 | 展示“现场识别结果 vs 表单填写结果” | 可替换 |

### 后续可扩展项

跑冒滴漏、油污、锈蚀、消防器材缺失、工业电视画面质量等可以作为正式项目扩展方向，不纳入两周首版承诺范围。

推荐默认视觉项：

```text
电动执行机构指示灯 / 面板状态识别
```

原因：

```text
它贴近巡检表单，画面效果直观，容易和“表单标红、触发复检、报告说明”串起来。
```

## 5. 时序模型适合预警的检查项

时序模型适合处理“连续变化、有阈值、能看趋势”的巡检项。首版用样例数据演示异常提示效果，不做现场模型训练。

### 首版可选项

| 时序检查项 | 对应业务价值 | demo 展示方式 | 建议 |
| --- | --- | --- | --- |
| 过滤器差压趋势异常 | 提前发现堵塞、压差接近标准上限等风险 | 展示趋势曲线、阈值线、异常提示、复检建议 | 首版推荐 |
| 管线压力异常 | 提醒压力波动或接近报警阈值 | 展示压力曲线和异常时间点 | 可替换 |
| 液位异常 | 提醒污油罐、泄压罐等液位接近上下限 | 展示液位趋势和风险提示 | 可替换 |

### 后续可扩展项

温度、流量、振动、电压、电流、频率、可燃气体浓度等可以作为正式项目扩展方向，不纳入两周首版承诺范围。

推荐默认时序项：

```text
过滤器差压趋势异常
```

原因：

```text
差压有明确标准，曲线容易讲清楚，异常原因容易解释，也容易触发复检清单和知识库依据命中。
```

## 6. 规则质检适合处理的问题

到位监控和表单质检不一定要做成模型。首版用规则更稳定，也更符合两周 demo 的边界。

| 质检点 | demo 展示效果 | 业务价值 |
| --- | --- | --- |
| 计划时间 vs 实际时间 | 标记迟到或巡检时长异常 | 管理人员不用逐条核查时间。 |
| 漏填 / 空值 | 自动标出未填写检查项 | 减少人工审表。 |
| 异常未说明 | 异常项缺少说明或照片时标红 | 提醒补充复检材料。 |
| 报警后仍填正常 | 设备有异常提示，但表单仍填正常 | 触发复检，不让风险停留在记录里。 |

路线覆盖需要轨迹、签到点或区域到达时间。当前首版不把路线覆盖作为默认能力，只在业务方能提供样例数据时作为加演。

## 7. 知识库和 Agent 的作用

知识库和 Agent 的目标不是炫技，而是把“复检依据”和“报告整理”做得更快。

| 能力 | demo 中做什么 | 业务价值 |
| --- | --- | --- |
| 知识库 | 命中巡检标准、阈值规则、复检步骤、演示案例、报告模板 | 异常出现时，能快速看到为什么要复检。 |
| Agent 复检辅助 | 生成复检清单、补拍建议、依据说明 | 复检人员不用手动翻制度。 |
| Agent 报告生成 | 生成巡检摘要、异常摘要、交接班关注项 | 管理侧能快速看到当天重点。 |
| 归档复用 | 把复检结论沉淀成案例 | 后续相似问题可复用经验。 |

首版知识库只准备最小集合：

```text
1 份巡检标准
1 组阈值规则
1 份复检步骤
1 条演示案例，有真实案例时替换为真实案例
1 个报告模板
```

## 8. 推荐演示故事

### 默认推荐故事

首版建议以“时序预警”为主冲突，“视觉识别”作为加演项。

```text
计量区例行巡检
  -> 到位/表单疑点
  -> 过滤器差压趋势异常
  -> 知识库命中标准和复检步骤
  -> Agent 生成复检清单
  -> 人工确认复检结论
  -> Agent 生成巡检摘要和交接班关注项
  -> 归档为案例
```

这个故事首版必须演清楚：

```text
AI 发现一个业务疑点，
知识库说明为什么它值得复检，
Agent 把复检依据和报告内容整理出来，
人工确认复检结论后再归档。
```

可加演视觉项：

```text
如果业务方能提供合适图片，
在同一条故事中加入“电动执行机构指示灯识别”，
展示视觉模型如何辅助表单标红和复检。
```

### 推荐演示步骤

```text
1. 打开“输油湘潭站日常巡检”任务。
2. 展示计划时间、实际时间、巡检区域和巡检表单。
3. 系统标记一个到位或填报疑点，例如实际开始时间晚于计划时间。
4. 系统发现过滤器差压趋势异常，并提示该项需要重点复检。
5. 巡检表单中该项仍填写正常，系统标记“数据异常但表单正常”的矛盾点。
6. 知识库命中差压标准、巡检要求和复检步骤。
7. Agent 生成复检清单：复核哪个设备、补拍什么证据、依据哪条标准。
8. 人工确认复检结果，形成复检结论。
9. Agent 基于复检结论生成巡检摘要和交接班关注项。
10. 系统归档为案例。
11. 如加演视觉，展示指示灯识别结果如何同步标红表单项。
```

## 9. 可选演示故事

业务方可以按汇报对象和素材条件选择演示重点。默认仍建议采用第 1 个故事。

| 排序 | 故事 | 最打动的角色 | 必需素材 | 两周风险 | 是否建议首版 |
| --- | --- | --- | --- | --- | --- |
| 1 | 时序预警 + 知识库依据 + Agent 复检辅助 + 人工确认 + Agent 报告 + 归档 | 管理人员、评委 | 差压或压力样例曲线、巡检表单、阈值标准 | 低 | 推荐作为主线 |
| 2 | 视觉识别加演 + 表单标红 + 复检取证 | 运维人员、评委 | 现场图片、表单项、识别结果样例 | 中 | 有图片素材时加演 |
| 3 | 到位监控 + 表单质检 + 管理看板 | 班组长、管理人员 | 计划/实际时间、表单填写记录 | 低 | 可作为辅助剧情 |
| 4 | 复检辅助 + 案例复用 | 复检人员、管理人员 | 标准条款、复检步骤、演示案例 | 低 | 可作为知识库亮点 |
| 5 | 巡检日报 / 交接班报告自动生成 | 管理人员 | 报告模板、巡检结果、异常摘要 | 低 | 必做轻量版 |

建议口径：

```text
首版不是把 5 个故事全部做成独立模块，
而是用一个主故事串起来，
再根据素材和汇报重点选择 1 个加演亮点。
```

首版页面控制在 4 个以内。

| 页面 | 展示内容 | 边界 |

| 巡检任务与到位看板 | 任务、计划/实际时间、人员、到位疑点、巡检时长疑点 | 不做正式人员考核。 |

## 11. 现有附件是否足够支撑 demo

结论：

```text
附件1和附件2已经足够支撑 demo 骨架、巡检表单、制度知识库、规则质检、Agent 复检辅助、人工确认和报告归档。
如果业务方能再补充少量趋势数据和现场图片，“时序预警”和“视觉识别”的现场感会更强。
```

现有材料可直接使用的部分：

| demo 能力 | 现有材料 | 支撑情况 | 说明 |
| --- | --- | --- | --- |
| 巡检业务流程 | 附件1：湖南公司油气站场巡检及交接班工作指引 | 足够 | 可支撑“定期巡检、IMS 巡检、异常上报、交接班、复检依据”的业务逻辑。 |
| 巡检表单和检查项 | 附件2：输油湘潭站日常巡检记录、巡检单 | 足够 | 已包含计划时间、实际时间、巡检路线、区域、检查项、标准、结果。 |
| 知识库内容 | 附件1工作指引、附件中的标准条款、交接班要求 | 足够 | 可拆成巡检标准、阈值规则、复检步骤、交接班要求、报告模板。 |
| 规则质检 | 附件2巡检记录 | 足够 | 可演示迟到、漏填、异常未说明、报警后仍填正常等规则。 |
| Agent 复检辅助 | 附件1工作指引、附件2巡检记录 | 足够 | 可生成复检清单、补拍建议和依据说明，供人工确认。 |
| Agent 报告归档 | 附件1交接班要求、人工确认后的复检结论 | 足够 | 可生成巡检摘要、异常摘要、交接班关注项和案例摘要。 |
| 时序预警 | 附件中已有标准和阈值描述 | 可演示，现场感可增强 | 首版可用演示趋势曲线呈现预警效果；如补充真实趋势数据，可信度更高。 |
| 视觉识别 | 附件2有视频抽查统计图片 | 可说明业务场景，现场感可增强 | 首版可展示识别效果；如补充单设备现场图片，视觉效果更直观。 |
| 案例复用 | 当前有作业卡和巡检记录 | 可演示 | 首版可整理 1 条演示案例；如业务方有真实复检案例，可提升说服力。 |

对业务方的建议口径：

```text
现有材料可以先开工搭 demo 骨架，不需要等待所有真实系统数据。
补充趋势数据和现场图片不是开工前提，而是增强演示现场感。
如果业务方暂时无法提供补充素材，首版仍可以用演示样例完成完整链路。
```

增强素材清单：

| 素材 | 用途 | 首版处理方式 |
| --- | --- | --- |
| 1 组过滤器差压或压力趋势数据 | 增强时序预警曲线、阈值线、异常提示的现场感 | 无真实趋势数据时，使用演示趋势曲线。 |
| 3-5 张电动执行机构、压力表、阀位或机柜指示灯现场图片 | 增强视觉识别加演效果 | 无现场图片时，使用演示图片和识别结果。 |
| 1 条真实异常或复检案例 | 增强知识库命中和案例复用的说服力 | 无真实案例时，整理一条“差压异常复检”演示案例。 |
| 1 个业务认可的报告或交接班摘要模板 | 支撑 Agent 报告输出 | 使用附件1交接班要求生成固定模板。 |

建议裁定：

```text
如果业务方只提供附件1和附件2：
  可以做“巡检任务 + 表单质检 + 知识库依据 + Agent 复检辅助 + 人工确认 + Agent 报告 + 归档”的完整闭环。

如果业务方再补 1 组趋势数据：
  时序预警主线会更接近现场真实数据。

如果业务方再补 3-5 张现场图片：
  视觉识别加演会更直观。
```

## 12. 业务方需要确认的事项

业务方主要确认“是否接受默认故事、能提供哪些素材、最想突出哪个亮点”。技术实现方式由 demo 方案确定，不要求业务方判断模型细节。

| 确认项 | 默认方案 | 需要业务方给出的结论 |
| --- | --- | --- |
| 是否接受默认主线故事 | 计量区例行巡检 + 过滤器差压趋势异常 + 知识库依据 + Agent 复检辅助 + 人工确认 + Agent 报告 + 归档 | 接受默认主线，并确认是否增加视觉加演。 |
| 是否补充增强素材 | 附件1和附件2已可支撑基础闭环 | 是否补充趋势数据、现场图片；真实复检案例作为可选增强。 |
| 若只能保留一个亮点 | 默认保留“时序预警 + 知识库依据 + Agent 复检辅助 + 人工确认 + Agent 报告 + 归档” | 业务方是否更希望突出视觉加演、管理质检或报告生成。 |

默认已经定下的内容：

```text
演示区域默认选计量区。
时序检查项默认选过滤器差压。
视觉检查项默认选电动执行机构指示灯。
知识库默认覆盖标准、阈值、复检步骤、演示案例、报告模板；有真实案例时替换为真实案例。
Agent 默认只做复检清单、巡检摘要和交接班关注项。
```

除非业务方明确要求替换，否则不再扩大首版范围。

## 13. 两周 demo 边界

首版 demo 控制在演示态，不做生产系统能力。

| 不做项 | 对业务方的说明 |
| --- | --- |
| 不接真实 PI / IMS / 视频 / WeAct | 先用样例数据和演示结果把演示闭环讲清楚。 |
| 不做现场模型训练 | 两周内不做视觉模型训练或复杂时序模型训练，只演示可见效果。 |
| 不覆盖完整巡检表单 | 只选择一个区域和少量代表检查项。 |
| 不把 AI 替代全部人工巡检 | AI 负责提醒和辅助，最终仍由人工确认。 |
| 不做正式考核和责任认定 | 到位监控只作为疑点提示。 |
| 不做真实派单、审批、销项 | 只做演示态复检清单和人工确认。 |
| 不做开放式问答 | Agent 只围绕巡检、复检、报告生成回答。 |
| 不做完整知识图谱 | 只做最小知识库，支撑演示链路。 |

## 14. 推荐定稿口径

这个 demo 演什么：

```text
演示 AI 如何嵌入现有巡检流程，
从巡检任务和表单出发，
发现一个设备或填报疑点，
命中知识库依据，
由 Agent 生成复检清单，
人工确认复检结论后，
再由 Agent 生成巡检摘要和交接班关注项。
```

这个 demo 不演什么：

```text
不演正式系统接入，
不演全量巡检自动化，
不演模型训练过程，
不演真实派单审批，
不演开放式通用 Agent。
```

业务方现在只需要确认什么：

```text
是否接受默认主线故事；
是否补充趋势数据、现场图片；
是否有真实复检案例可作为增强素材；
如果只能突出一个亮点，是突出时序预警主线、视觉加演、管理质检，还是 Agent 报告归档。
```

确认后两周内能看到什么：

```text
一套可点击、可演示、能讲完整业务闭环的 demo：
巡检任务看板、巡检表单标红、AI 疑点提示、知识库依据、复检清单、人工确认、Agent 巡检报告、案例归档。
```
