# 巡检质量智能分析助手 demo 演示路线与页面交互方案

本文是参赛 demo 开发前的演示蓝图，用来先把“演示者怎么点、页面怎么反馈、素材怎么进入剧情、数据后续怎么整理”说清楚。

它只管演示编排，不管技术实现、不管 seed 结构、不管 API 合同，也不提前创建结构化数据目录。后续开发时，页面实现、数据整理、接口设计和报告模板应以本文冻结的演示路线为上游依据，再落到 [巡检质量智能分析助手-demo-开发指导.md](巡检质量智能分析助手-demo-开发指导.md) 和 [巡检质量智能分析助手-demo-技术实施定版方案.md](巡检质量智能分析助手-demo-技术实施定版方案.md)。

## 1. 本次要达成的目标

当前目标不是马上写代码，也不是一次性造一批复杂数据，而是先把参赛 demo 具象化：

```text
一个可投屏的大屏主页
  -> 演示者通过点击推进故事
  -> 页面给出清晰反馈、联动和动效
  -> 用现有巡检记录、趋势文件、关键帧和附件材料支撑业务逻辑
  -> 最后形成复检确认、报告生成、案例归档的闭环
```

本文需要回答 6 个问题：

| 问题 | 本文答案 |
| --- | --- |
| 演示主线是什么 | 固定一条“计量区巡检质检 + 差压趋势疑点 + 复检报告”的主剧情。 |
| 需要哪些页面 | 1 个主页大屏 + 3 个业务分页 + 1 个全局 Agent 抽屉。 |
| 演示者怎么点击 | 每一页都有明确点击入口、选中态、证据联动和下一步按钮。 |
| 页面怎么反馈 | 用步骤点亮、风险卡翻转、图表高亮、图片框选、抽屉展开、报告渐显制造演示感。 |
| 现有素材怎么用 | 优先使用 `附件2` 巡检记录、`assets/data` 趋势 Excel、现场关键帧和统计截图。 |
| 后续数据怎么准备 | 先保留原始资料，开发阶段再整理为 JSON / CSV / 图片元数据等演示数据。 |

本文不做这些事：

| 暂不做 | 原因 |
| --- | --- |
| 不新建结构化数据目录 | 当前阶段先定路线和素材口径，避免边想边拆数据。 |
| 不承诺全量巡检平台 | 参赛 demo 需要故事集中、效果集中。 |
| 不做真实接口集成 | 当前以可交互演示为主，真实 PI / 视频 / IMS / WeAct 接入会放大范围。 |
| 不做开放式聊天机器人 | Agent 只服务复检、依据解释和报告生成。 |

## 2. 演示心智模型

这个 demo 应该像一个“巡检质量智能指挥台”，而不是表单系统或静态 PPT。

推荐演示闭环：

```text
主页大屏发现风险
  -> 点击进入巡检分析
  -> 表单、曲线、图片联动证明疑点
  -> 点击生成复检清单
  -> 人工确认复检结论
  -> Agent 生成报告和交接班关注项
  -> 归档为可复用案例
  -> 回到主页展示闭环完成
```

评委应该在 5-8 分钟内看到三个记忆点：

| 记忆点 | 页面表现 |
| --- | --- |
| AI 主动发现疑点 | 大屏风险卡和流程步骤自动亮起。 |
| 疑点不是孤立告警 | 表单“正常”、差压趋势异常、现场关键帧和标准依据互相联动。 |
| AI 能推动业务动作 | 复检清单、人工确认、报告快照和案例归档形成闭环。 |

## 3. 推荐演示路线

首版演示建议控制在 7 分钟左右。演示者只需要沿着固定按钮点击，不依赖长篇口播。

| 时间 | 演示动作 | 页面 | 页面反馈 | 讲解重点 |
| --- | --- | --- | --- | --- |
| 0:00-0:40 | 打开主页大屏 | `/` | 站场标题、风险评分、AI 巡检链路逐段点亮。 | 这是 AI 增强巡检，不是重做巡检系统。 |
| 0:40-1:20 | 点击“本轮重点任务” | `/` | 任务卡展开，显示计划开始 `2026-07-21 03:30:05`、实际开始 `2026-07-21 04:00:27`、巡检人廖震宇。 | 自动质检巡检到位和任务时长。 |
| 1:20-2:40 | 点击“计量区过滤器差压疑点” | `/inspection/:taskId` | 页面跳转并定位到计量区过滤器，差压趋势图出现阈值线和异常窗口。 | 表单填写正常，但历史趋势接近风险线。 |
| 2:40-3:30 | 点击巡检表单第 73 项 | `/inspection/:taskId` | 表单行、图表时间窗、证据卡同步高亮。 | 巡检结果“正常”和趋势疑点形成冲突。 |
| 3:30-4:10 | 点击“查看依据” | `/inspection/:taskId` | 证据链抽屉从右侧滑入，按规则命中、标准条款、复检步骤、历史案例四段展示。 | 疑点有依据，不是黑盒提示。 |
| 4:10-5:10 | 点击“生成复检清单” | `/recheck/:taskId` | 知识依据命中，复检 checklist 逐条生成。 | AI 把疑点转成可执行复检动作。 |
| 5:10-5:50 | 点击“人工确认复检” | `/recheck/:taskId` | 弹出确认窗口；确认后状态从橙色“待确认”切换为绿色“已确认”，报告按钮解锁。 | 安全生产边界保留人工确认。 |
| 5:50-6:50 | 点击“生成报告快照” | `/reports/:taskId` | 巡检摘要、异常摘要、交接班关注项、案例标签分段渐显。 | 巡检经验沉淀为报告和案例。 |
| 6:50-7:20 | 回到主页 | `/` | 主流程变为“已复检 / 已归档”，风险卡变为闭环状态。 | 演示闭环完成。 |

可选加演不超过 1 分钟：

| 加演 | 用法 | 边界 |
| --- | --- | --- |
| 现场关键帧 | 在分析页切换到“视觉加演”标签，显示识别框、标签和置信度。 | 当前关键帧不强绑定计量区差压，默认只做氛围增强和视觉能力展示。 |
| Agent 抽屉固定问答 | 点击“为什么需要复检”“交接班关注什么”两个固定问题。 | 不做自由输入，不让现场随机问答影响演示节奏。 |
| 视频监控截图统计 | 用作大屏数据源卡或报告页背景材料。 | 不做 OCR 识别主线，避免偏离主剧情。 |

首版页面对象保持轻量：

| 对象 | 数量 | 用途 |
| --- | --- | --- |
| 主页面 | 4 个 | 主页大屏、巡检分析、复检工作台、报告归档。 |
| 抽屉 | 2 个 | 证据链抽屉、Agent 抽屉。 |
| 弹窗 | 1 个 | 人工确认弹窗。 |

## 4. 页面结构与交互方案

### 4.1 主页大屏：巡检质量智能指挥台

路由：`/`

页面目标：第一眼建立“高大上、工业、AI 指挥台”的观感，同时给演示者清晰入口。

建议布局：

| 区域 | 内容 | 交互 |
| --- | --- | --- |
| 顶部状态栏 | 长郴-湘潭站、演示日期、当前任务、数据版本、AI 运行状态。 | 点击站场名称可展开数据源概览。 |
| 中央主视觉 | 巡检流程链路：任务、表单、时序、视觉、知识库、复检、报告、归档。 | 演示推进时节点逐段点亮。 |
| 风险总览 | 风险评分、疑点数量、待复检数量、报告状态。 | 首次进入数字翻牌一次，后续保持稳定。 |
| 本轮重点任务 | 计量区例行巡检任务卡。 | 点击展开计划/实际时间、人员、路线和疑点摘要。 |
| 疑点卡片 | 到位疑点、差压趋势疑点、表单冲突疑点、视觉辅助证据。 | 点击卡片进入对应页面并自动定位证据。 |
| 数据源卡 | 巡检记录、趋势数据、现场关键帧、知识依据。 | 悬停显示来源，不做复杂数据管理。 |

主页必须有的点击反馈：

| 点击对象 | 反馈 |
| --- | --- |
| 本轮重点任务 | 卡片展开，任务路线高亮，右侧出现“进入巡检分析”按钮。 |
| 差压趋势疑点 | 进入分析页后自动选中第 73 项和差压图。 |
| 表单冲突疑点 | 进入分析页后表格行和冲突提示卡同步高亮。 |
| 已归档案例 | 演示末尾回到主页时可点击查看报告快照。 |

视觉取舍：

| 建议做 | 暂不做 |
| --- | --- |
| 深色工业大屏、流程光带、风险卡、状态徽章、图表小窗。 | 复杂 3D 站场、真地图、实时视频墙、持续闪烁动画。 |

### 4.2 巡检分析页：表单、曲线、关键帧联动

路由：`/inspection/:taskId`

页面目标：制造主冲突，让评委看到“巡检表单正常，但 AI 从趋势和证据链发现需要复检”。

建议布局：

```text
左侧：精选巡检项表格
右上：差压趋势图
右中：现场关键帧 / 视觉辅助证据
右下：AI 疑点解释和证据链入口
```

核心交互：

| 操作 | 页面反馈 |
| --- | --- |
| 从主页点击差压疑点 | 页面切换控制在 200-300ms，目标表单行高亮，趋势图异常区闪一次。 |
| 点击第 73 项“计量区 / 过滤器 / 差压” | 表格行固定选中，图表显示 `0.1MPa` 阈值线和异常窗口，右下提示“表单正常但趋势接近预警”。 |
| 鼠标悬停趋势异常窗口 | Tooltip 显示采集时间、数据值、阈值、趋势判断。 |
| 点击图表异常窗口 | 左侧表格自动滚动到相关巡检项，证据链按钮闪一次。 |
| 点击现场关键帧 | 图片区域叠加识别框、设备标签、拍摄时间和来源文件名。 |
| 点击“查看依据” | 证据抽屉打开，先显示 300-500ms 局部 Skeleton，再按规则、标准、步骤、案例依次出现。 |

首版精选巡检项建议：

| 来源 | 可用项 | 用法 |
| --- | --- | --- |
| `输油湘潭站日常巡检记录.md` | 计量区第 73 项：过滤器差压，标准为过滤分离器差压小于 `0.1MPa`，结果正常。 | 主冲突核心。 |
| `输油湘潭站日常巡检记录.md` | 计量区第 63 项：污油罐压力 `0.06`。 | 辅助数据项，展示并非所有数据异常。 |
| `输油湘潭站日常巡检记录.md` | 计量区第 69 项：液位计示值检查。 | 可与液位趋势作为备用剧情。 |
| `输油湘潭站日常巡检记录.md` | 计量区第 76-78 项：电动执行机构显示面板、指示灯、现场状态。 | 适合接现场关键帧做视觉加演。 |
| `输油湘潭站日常巡检记录.md` | PLC 机房第 288-296 项：PLC 机柜灯态。 | 适合用 PLC 关键帧做第二证据，不作为主线。 |

### 4.3 复检工作台：证据链转动作

路由：`/recheck/:taskId`

页面目标：证明系统不是只报风险，而是能给出依据、步骤和人工确认入口。

建议布局：

| 模块 | 内容 | 交互 |
| --- | --- | --- |
| 疑点摘要 | 设备、区域、触发时间窗、风险等级、冲突说明。 | 点击摘要可回到分析页定位证据。 |
| 知识依据 | 差压阈值、巡检标准、复检步骤、历史案例。 | 命中条款高亮，来源可展开。 |
| 复检清单 | 复核点位、补拍建议、现场确认项、备注。 | checklist 可逐项勾选。 |
| 人工确认 | 复检结论、确认人、确认时间、备注。 | 点击确认后状态变为已确认，报告入口解锁。 |

人工确认弹窗只保留一次：

| 字段 | 用途 |
| --- | --- |
| 复检结论 | 固定可选“已复核，建议纳入交接班关注”。 |
| 确认备注 | 演示可预置一条备注。 |
| 纳入交接班 | 默认勾选，确认后报告页生成关注项。 |

复检清单首版建议：

| 复检项 | 展示内容 |
| --- | --- |
| 复核过滤器差压 | 核对现场差压表与历史趋势，确认是否接近 `0.1MPa`。 |
| 补拍过滤器铭牌和差压表 | 要求补拍清晰表盘、设备编号、周边状态。 |
| 核对执行机构状态 | 确认指示灯、阀位、远传控制状态与表单一致。 |
| 记录交接班关注项 | 建议下一班关注差压变化和过滤器状态。 |

交互边界：

| 做 | 不做 |
| --- | --- |
| 演示态人工确认、状态切换、报告解锁。 | 真实派单、审批流、销项闭环、责任认定。 |

### 4.4 报告归档页：从疑点到案例

路由：`/reports/:taskId`

页面目标：把前面点击出来的结果收束成一份“可汇报、可交接、可归档”的成果。

建议结构：

| 区域 | 内容 |
| --- | --- |
| 报告头 | 站场、任务、巡检人、计划/实际时间、报告生成时间、规则版本。 |
| 巡检摘要 | 本轮到位情况、精选巡检项、AI 发现的主要疑点。 |
| 异常摘要 | 差压趋势疑点、表单冲突、视觉辅助证据。 |
| 复检结论 | 人工确认状态、复检建议、后续关注动作。 |
| 交接班关注项 | 下一班重点关注设备、建议复核时间、补拍要求。 |
| 案例归档 | 案例标题、标签、证据来源、可复用说明。 |

页面反馈：

| 操作 | 反馈 |
| --- | --- |
| 点击“生成报告快照” | 各段落按“摘要 -> 依据 -> 建议 -> 归档”顺序渐显。 |
| 点击“归档为案例” | 案例标签点亮，状态变为“已归档”。 |
| 点击“回到主页” | 主页流程链路显示已闭环。 |

### 4.5 全局 Agent 抽屉

不建议做独立聊天页。Agent 作为全局抽屉出现，服务固定演示问题。

| 固定问题 | 输出内容 |
| --- | --- |
| 为什么这个差压趋势需要复检？ | 阈值、趋势窗口、表单冲突、复检建议。 |
| 本次巡检有哪些质量疑点？ | 到位疑点、表单疑点、时序疑点、视觉辅助证据。 |
| 复检人员需要补拍什么？ | 点位、拍摄角度、需要包含的设备信息。 |
| 交接班要关注什么？ | 后续关注设备、风险说明、建议动作。 |

Agent 抽屉的边界：

| 做 | 不做 |
| --- | --- |
| 固定问题、固定场景、引用证据、生成摘要。 | 开放输入、任意问答、现场临时扩展业务范围。 |

### 4.6 基础交互和可访问性约束

这些约束用于避免 demo 看起来炫但不可控：

| 约束 | 要求 |
| --- | --- |
| 字号 | 大屏主信息尽量 `18px+`，关键数字和结论 `24px+`。 |
| 状态表达 | 不只靠红绿区分，必须同时显示图标和文字，如“异常”“待确认”“已确认”。 |
| 焦点顺序 | 顶部步骤条 -> 疑点胶囊 -> 主内容 -> 右侧操作按钮 -> 抽屉 / 弹窗。 |
| 抽屉和弹窗 | 打开后焦点落到标题或主按钮；`Esc` 关闭，`Enter` 触发主动作。 |
| Loading | 使用局部 Skeleton，不用全屏转圈；“生成复检清单”可 loading 1-2 秒。 |
| 空态 | 明确显示“本场景未启用视觉加演”或“缺少证据，暂不可归档”，不要静默隐藏。 |

## 6. 数据准备格式

本阶段只定义“演示需要哪些信息、优先用什么格式准备”，不立即拆分数据目录，不定义 seed 字段合同、数据库表结构或 API 合同。

格式原则：

| 数据类型 | 当前阶段推荐 | 后续开发阶段 |
| --- | --- | --- |
| 时序数据 | 保留 Excel 原始文件，必要时整理一份轻量 CSV。 | 是否转结构化演示数据由开发指导和技术方案决定。 |
| 巡检任务和表单 | 先用 Markdown 表格或人工整理清单确认范围。 | 再整理为导入用 JSON。 |
| 图片和关键帧 | 继续使用 PNG / JPG 原文件，另补一份元数据清单。 | 再复制到 demo assets 并补标注数据。 |
| 知识依据 | 先用 Markdown 摘录条款和复检说明。 | 再按知识条目导入。 |
| 演示脚本 | 先用 Markdown 写点击顺序和讲解点。 | 如前端需要自动高亮，再转结构化脚本。 |

### 6.1 时序数据

原始资料可以继续保留为 Excel。进入页面展示前，建议先整理成一份轻量 CSV，因为 CSV 更方便人工检查，也更适合先验证曲线是否能支撑演示。

CSV 信息清单：

| 信息 | 用途 |
| --- | --- |
| 站场 | 页面筛选和来源展示。 |
| 区域 / 设备 | 与巡检表单项做候选映射。 |
| 指标名称 | 区分差压、压力、液位等曲线。 |
| 单位 | 图表坐标轴和阈值说明。 |
| 采集时间 | 趋势横轴和异常时间窗。 |
| 数值 | 趋势曲线主数据。 |
| 数据质量 | 判断是否展示或标注异常点。 |
| 来源文件 | 证据追溯。 |

说明：`湘潭站差压GL-11.xls` 可以作为差压主曲线候选，但当前只能证明趋势文件名包含 `GL-11`，不能直接证明它就是巡检记录第 73 项对应的过滤器。开发前需要把 `GL-11` 与“计量区 / 过滤器 / 差压”做一次业务确认。

时序数据需要你后续确认：

| 需要确认 | 说明 |
| --- | --- |
| 主线使用差压、压力还是液位 | 推荐差压，因为巡检记录已有 `0.1MPa` 标准。 |
| 展示时间窗 | 推荐 48-72 小时，图上能看出趋势抬升。 |
| 粒度 | 原始粒度可保留，demo 展示可抽样到 5-15 分钟。 |
| 是否允许演示构造异常窗口 | 如果真实曲线不够明显，可在不改变业务口径的前提下为演示增强。 |

图片文件继续用 PNG / JPG。当前阶段不需要标注完整识别结果，只需要补一份元数据清单，说明每张图在演示里承担什么角色。

关键帧元数据清单：

### 6.5 演示脚本

演示脚本当前只需要 Markdown。它应该写清每一步点哪里、页面反馈是什么、讲一句什么，不需要写路由字段或高亮字段。

演示脚本清单：

| 信息 | 用途 |
| --- | --- |
| 步骤序号 | 控制演示顺序。 |

## 7. 演示成熟度里程碑

本节只定义 demo 从“想清楚”到“可展示”的确认顺序，不维护开发任务拆解、实现策略、seed、接口或数据库细节。具体开发阶段和工程实现仍维护在 [巡检质量智能分析助手-demo-开发指导.md](巡检质量智能分析助手-demo-开发指导.md)。

### 阶段 0：路线冻结

目标：确认本文主线、页面、点击路径和素材映射。

确认标准：

| 确认项 | 标准 |
| --- | --- |
| 演示路线 | 5-8 分钟路线能按点击顺序讲完。 |
| 页面范围 | 固定 4 个页面和 1 个 Agent 抽屉。 |
| 主线素材 | 明确巡检记录、差压趋势、关键帧、知识依据的用途。 |
| 数据口径 | 确认先保留原始资料，后续再整理 JSON / CSV / 图片元数据。 |

### 阶段 1：屏幕走查

目标：确认每一页的屏幕效果和点击反馈符合演示路线。

确认标准：

| 确认项 | 标准 |
| --- | --- |
| 主页大屏 | 第一屏能看出站场、任务、疑点、AI 闭环。 |
| 页面路径 | 从主页到分析、复检、报告的路线清楚。 |
| 点击反馈 | 选中态、高亮、抽屉、弹窗、报告渐显有明确反馈。 |
| 演示节奏 | 演示者不需要解释按钮在哪里。 |

### 阶段 2：素材挂载

目标：确认现有资料在页面上承担清楚的叙事角色，减少纯假数据感。

确认标准：

| 确认项 | 标准 |
| --- | --- |
| 巡检记录 | 精选任务信息和第 73 项等表单项能支撑主线。 |
| 趋势曲线 | 差压或压力 / 液位曲线能支撑阈值线和异常窗口。 |
| 关键帧 | 至少 1-3 张现场图片有明确用途。 |
| 素材来源 | 页面可展示来源文件名或来源说明。 |

### 阶段 3：证据闭环

目标：确认疑点、依据、复检和报告之间能闭环，评委能看懂“为什么发现、为什么复检、复检后沉淀什么”。

确认标准：

| 确认项 | 标准 |
| --- | --- |
| 证据联动 | 页面能从任务、表单、曲线、关键帧和依据中回看来源。 |
| 规则口径 | 到位疑点、差压接近阈值、表单冲突等规则能讲清来源。 |
| 报告快照 | 页面能展示巡检摘要、复检结论和交接班关注项。 |
| 证据追溯 | 每个疑点能回到数据源、规则和素材。 |

### 阶段 4：参赛彩排

目标：确认 demo 适合投屏、适合评委观看、适合现场稳定演示。

确认标准：

| 确认项 | 标准 |
| --- | --- |
| 视觉统一 | 工业大屏风格统一，投屏可读。 |
| 节奏稳定 | 7 分钟内能完整演示，不需要临场找按钮。 |
| 失败面收敛 | 不暴露未完成菜单、空页面、报错堆栈。 |
| 演示备份 | 准备固定数据、固定脚本、关键截图或录屏备用。 |

## 8. 当前需要确认的事项

在进入开发前，建议先确认下面事项：

| 确认项 | 推荐默认 |
| --- | --- |
| 主线区域 | 计量区。 |
| 主线设备 | 计量区过滤器；`湘潭站差压GL-11.xls` 与该设备的对应关系待确认。 |
| 主线时序指标 | 差压，阈值按 `0.1MPa` 展示。 |
| 视觉加演 | 先用已有关键帧做识别框和状态标签，不训练模型；如没有计量区对应图片，视觉从主线剥离为可选加演。 |
| 表单项数量 | 首版 8-12 条精选项，不搬完整巡检表。 |
| Agent 形式 | 全局抽屉 + 固定问题，不做开放问答。 |
| 报告模板 | 首版展示页面报告快照，PDF / Excel 导出后置。 |
| 数据处理顺序 | 先页面演示路线，再素材映射，再进入结构化数据整理。 |

如果后续要补充素材，优先补这些：

| 素材 | 推荐格式 | 用途 |
| --- | --- | --- |
| 过滤器或差压表现场图片 | PNG / JPG，尽量清晰、无遮挡。 | 主线视觉证据。 |
| 过滤器差压历史数据 | Excel / CSV，包含时间和值。 | 主线趋势图。 |
| 真实复检记录或交接班记录 | Markdown / Word / 截图均可。 | 报告和知识依据更真实。 |
| 监控视频片段 | MP4 或关键帧 PNG。 | 只抽关键帧进入 demo，不做实时视频流。 |

## 9. 后续结构化数据的拆分时机

只有当本文的演示路线确认后，才开始拆结构化数据。当前只定义触发条件，不在本文维护目录、字段或接口合同。

| 触发条件 | 可以开始整理的内容 |
| --- | --- |
| 主线区域和设备确认 | 从 `附件2` 抽取 1 条任务和 8-12 条表单项。 |
| 主趋势指标确认 | 从趋势 Excel 中选 1 条主曲线，整理为可检查的 CSV。 |
| 视觉加演范围确认 | 从关键帧中选 1-3 张图片，补图片元数据清单。 |
| 复检口径确认 | 从工作指引和巡检记录中抽 5-8 条知识依据。 |
| 点击路线确认 | 编写 1 份 Markdown 演示脚本。 |
| 开发阶段启动 | 由开发指导和技术实施方案决定是否生成结构化演示数据、接口数据和报告模板。 |

这样做的目的，是避免还没想清楚演示效果就先造一批难维护的数据。
