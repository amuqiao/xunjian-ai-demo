# 巡检质量智能分析助手 demo AI 赋能演示定稿方案

本文是巡检质量智能分析助手 demo 的当前对外方案，用于业务沟通、立项汇报、演示范围确认和验收口径确认。

它不负责技术栈、数据模型、部署方式和模型接入细节；这些内容维护在 [巡检质量智能分析助手-demo-技术实施定版方案](巡检质量智能分析助手-demo-技术实施定版方案.md)。

## 0. 结论速览

### demo 心智模型

这个 demo 不是做一个新的巡检系统，而是演示多源巡检数据如何被 AI 理解、关联、解释，并通过 Agent 推动复检和报告沉淀。

核心闭环：

```text
数据进入
  -> AI 发现疑点
  -> 知识解释依据
  -> Agent 辅助复检
  -> 人工确认
  -> 报告沉淀
```

演示主线必须始终围绕一条业务故事展开：

```text
巡检任务
  -> 时序数据发现趋势异常
  -> 视觉模型发现现场异常
  -> 表单/规则发现巡检质量疑点
  -> 知识库解释异常依据和复检标准
  -> Agent 生成复检建议
  -> 人工确认
  -> 自动生成报告和案例沉淀
```

开发和演示时不要把它做成单纯大屏、聊天机器人、图表看板或孤立的视觉识别 demo。每个页面、接口和交互都必须服务于“发现疑点、解释依据、推动复检、形成报告”中的一个环节。

### 首版定位

第一版定为 `两周可完成的 AI 赋能演示 demo`：

```text
现有定期巡检流程
  + 固定样例巡检任务
  + 少量表单检查项
  + 轻量时序异常提示
  + 预置视觉识别结果
  + 规则/事件质检
  + 知识库依据
  + Agent 复检清单和报告生成
  + 人工确认和归档
```

一句话口径：

```text
两周 demo 不做巡检平台，只演示 AI 如何增强现有巡检流程。
```

第一版要证明的不是“模型已经生产可用”，而是：

```text
AI 可以嵌入现有巡检流程，
帮助发现疑点、命中复检依据、生成复检清单和巡检报告，
让巡检工作从人工记录和事后核查，
升级为 AI 提醒、人工确认、经验沉淀。
```

## 2. 先定性质

这次 demo 不是把现有巡检系统重做一遍，也不是单独做一个 AI 预警页面。业务方已有比较固定的巡检流程：

```text
定期巡检
  -> 运维人员到现场
  -> 按巡检表单逐项检查并填写结果
  -> 管理侧监控人员是否按时巡检
  -> 异常或疑点触发复检
  -> 形成记录、报告、交接班关注项和归档
```

demo 要证明的是：

```text
AI 可以嵌入这条既有巡检流程，
在部分检查项识别、设备趋势预警、表单质检、复检依据命中、报告生成上提效。
```

第一版定位为 `立项演示 PoC`，不是试点 MVP，也不是正式项目。

| 层级 | 适合当前 demo 吗 | 处理方式 |
| --- | --- | --- |
| 立项 / 比赛演示 PoC | 适合 | 用固定样例跑通 AI 增强巡检流程。 |
| 试点 MVP | 下一阶段 | 需要真实接口、真实部署、权限、审计、联调和试点验收。 |
| 正式项目 / 区域推广 | 不适合作为首版 | 需要多站点、多设备、多规则、真实闭环和运维体系。 |

申报材料中的人工核查降低、统计工时缩减、人力投入减少等收益口径，可以作为预期价值展示，不作为两周 demo 验收指标。首版只按冻结样例、冻结规则、冻结脚本和固定输出验收。

业务痛点可以压缩成一句话：

```text
巡检数据被记录了，但疑点、依据、复检动作、报告和案例仍靠人工串起来。
```

所以当前 demo 只证明 AI 如何把记录、图片、曲线、标准和复检结果转成疑点、依据、建议、报告和案例，不把范围扩大成完整人员考核或复合风险平台。

## 3. 核心演示主线

定版主线：

```text
巡检任务
  -> 巡检表单
  -> AI 发现疑点
  -> 知识库给出依据
  -> Agent 生成复检清单
  -> 人工确认复检结论
  -> Agent 生成报告
  -> 归档复用
```

默认演示故事：

```text
计量区例行巡检
  -> 到位/表单疑点
  -> 过滤器差压趋势异常
  -> 巡检表单仍填写正常
  -> 知识库命中差压标准和复检步骤
  -> Agent 生成复检清单和补拍建议
  -> 人工确认复检结论
  -> Agent 生成巡检摘要和交接班关注项
  -> 归档为案例
```

可加演视觉项：

```text
电动执行机构指示灯 / 阀位 / 压力表读数识别
  -> 展示识别框、状态标签、置信度
  -> 自动标红表单项
  -> 触发复检建议
```

## 4. AI 插点和能力映射

不要从“训练什么模型”开始讲，而要从业务流程讲 AI 放在哪里。

| 流程节点 | AI 赋能点 | 首版做法 |
| --- | --- | --- |
| 巡检任务下发 | 提醒本轮重点关注区域、设备和检查项 | 使用固定演示任务和样例检查项。 |
| 到位监控 | 识别迟到、巡检时长异常、路线覆盖疑点 | 先做计划时间与实际时间规则；路线覆盖只作为可选模拟字段。 |
| 表单填写 | 标红漏填、异常未说明、长期全正常等疑点 | 使用轻量规则，不做复杂模型裁决。 |
| 时序预警 | 发现压力、差压、液位、温度等趋势异常 | 首版默认选择过滤器差压或压力曲线。 |
| 视觉辅助 | 识别仪表读数、阀位、指示灯、机柜灯态等可见状态 | 使用 1 个代表项和预置识别结果。 |
| 复检触发 | 根据异常和规则生成复检清单 | 输出复检点、依据、补拍建议。 |
| 知识库命中 | 命中标准、阈值、复检步骤、历史案例 | 只建设最小知识集合。 |
| Agent 报告 | 生成巡检摘要、异常摘要、交接班关注项 | 限定模板和固定问题，不做开放 Agent。 |

## 5. 两周首版范围

首版只做可演示的最小闭环。

| 功能 | 页面表现 | 首版实现深度 |
| --- | --- | --- |
| 巡检任务与到位监控 | 展示任务、计划/实际时间、人员、到位疑点 | 样例巡检记录 + 轻量规则。 |
| 巡检表单展示 | 展示区域、检查项、标准、结果、异常标红 | 使用少量代表性表单项。 |
| 时序异常提示 | 展示曲线、阈值线、趋势偏移、异常提示 | 模拟曲线或样例 CSV + 轻量计算。 |
| 视觉辅助识别 | 展示图片、识别框、标签、置信度、表单回填 | 预置图片和识别结果。 |
| 复检清单 | 生成复检点位、原因、补拍证据和人工确认项 | 规则 + 知识库命中。 |
| 知识库依据 | 展示标准、阈值、复检步骤、历史案例 | 最小知识库。 |
| Agent 报告 | 生成巡检摘要、异常摘要、交接班关注项 | 固定模板，可选模型润色。 |

页面控制在 4 个以内：

| 页面 | 展示什么 | 不做什么 |
| --- | --- | --- |
| 巡检任务与到位看板 | 任务、计划/实际时间、人员、到位疑点、巡检时长疑点 | 不做正式人员考核，不默认做路线覆盖。 |
| 巡检表单 + AI 辅助识别 | 表单项、视觉识别结果、时序异常提示、表单标红 | 不做全量表单自动识别。 |
| 异常/疑点复检台 | 复检原因、依据、补拍建议、人工确认 | 不做真实派单审批。 |
| 报告归档与案例复用 | 巡检报告、交接班关注项、历史案例命中 | 不做完整知识图谱。 |

## 6. 必须保留、可以简化、不做

### 6.1 必须保留

| 能力 | 原因 |
| --- | --- |
| 时序异常提示 | 证明 AI 能在巡检前或巡检中提示重点复核点。 |
| 表单 / 到位质检 | 直接回应管理侧人工核查成本高的问题。 |
| 知识库依据 | 让复检建议有标准、阈值和步骤来源。 |
| Agent 复检清单 | 把 AI 发现的疑点转化为可执行动作。 |
| Agent 报告 | 让管理侧看到报告和交接班材料自动生成的价值。 |
| 人工确认 | 保持安全生产和管理责任边界。 |

### 6.2 可以首版简化

| 能力 | 简化方式 |
| --- | --- |
| 视觉模型 | 只选 1 个代表项，使用预置识别结果展示。 |
| 路线覆盖 | 只有业务方能提供轨迹或签到点样例时才加演。 |
| 知识库 | 只做巡检标准、阈值、复检步骤、1 条历史案例和 1 个报告模板。 |
| 聊天 / Agent | 限定在复检清单、巡检摘要、交接班关注项，不做开放问答。 |
| 报表导出 | 页面展示优先；PDF/Excel 作为可选增强。 |

### 6.3 两周内不做

| 不做项 | 原因 |
| --- | --- |
| 不接真实 PI / IMS / 视频 / WeAct | 会变成系统集成项目，接口、权限和网络不可控。 |
| 不训练 YOLO 或深度时序模型 | 两周 demo 重点是演示 AI 赋能业务，不是模型研发。 |
| 不覆盖完整巡检表单 | 表单项太多，首版只选 1 个区域和少量代表项。 |
| 不把视觉替代全部人工巡检 | 异响、异味、手动检查、工具检查仍需人工确认。 |
| 不做正式考核、扣分、责任认定 | 到位监控只作为疑点提示，不做管理裁决。 |
| 不做真实派单、审批、销项 | 只做演示态复检清单和人工确认。 |
| 不做开放式 Agent | 只做巡检、复检、报告相关固定能力。 |
| 不做完整知识图谱 | 只做标准、阈值、复检步骤、历史案例的最小知识库。 |
| 不做 RPA / 数据湖 / BI / PPS / 生产日报 / 审批分发 / 文件审阅 | 这些是相邻平台能力，不属于巡检 AI 赋能两周 demo。 |
| 不承诺现场开放式自由问答 | 首版按固定脚本和限定输出验收。 |

## 7. 业务方需要确认的 6 件事

为了保证两周内能做出演示效果，业务方需要先确认下面 6 件事。

| 确认项 | 推荐默认 | 可选替换 |
| --- | --- | --- |
| 主区域 | 阀组区或计量区 | 泵区、站控室、配电间。 |
| 视觉检查项 | 执行机构指示灯 / 阀位 / 压力表读数选 1 个 | 消防器材、机柜指示灯、外观泄漏。 |
| 时序检查项 | 过滤器差压 / 压力 / 液位选 1 个 | 温度、流量、电压、电流。 |
| 巡检质检点 | 迟到、漏填、异常未说明选 1-2 个 | 长期全正常；路线覆盖需额外模拟轨迹或签到点。 |
| 知识库材料 | 巡检标准、阈值、复检步骤、1 条历史案例 | 交接班记录、报告模板。 |
| Agent 输出 | 巡检摘要、复检清单、交接班关注项 | 周报、相似案例说明。 |

这 6 件事确认后，首版 demo 范围即定稿。后续可以补场景，但不能把首版扩展成完整巡检系统。

同时需要指定唯一业务确认人和冻结时间。确认后冻结 `demo 数据集`、`规则口径`、`演示脚本` 和 `报告模板`；冻结后新增内容按变更处理。

## 8. 冻结项和验收口径

开发前建议冻结：

| 冻结项 | 需要冻结什么 | 不冻结的后果 |
| --- | --- | --- |
| demo 目标 | 演示对象、演示目的、成功标准 | 页面和脚本容易做偏。 |
| 演示故事 | 区域、设备、表单项、疑点、复检和报告主线 | 功能范围会发散。 |
| 数据样例 | 巡检任务、表单记录、时序曲线、图片、标准、案例 | 无法判断逻辑能否跑通。 |
| 规则口径 | 迟到、漏填、异常未说明、阈值异常、复检触发条件 | 页面、报告和 Agent 输出都会变化。 |
| 页面和输出 | 4 个页面、Agent 输出、报告模板 | 临时新增会改变工期。 |
| 验收口径 | 固定数据、固定脚本、固定确认项 | 容易把 demo 验收扩大成正式系统验收。 |

定版验收口径：

> 在双方预先确认的数据样例、规则口径和演示脚本下，系统可稳定完成巡检任务展示、AI 疑点发现、知识库依据命中、复检清单生成、人工确认、巡检报告生成和案例归档，并且关键结论可追溯到来源数据或规则依据。

建议验收明细：

| 验收项 | 建议标准 |
| --- | --- |
| 数据 | 加载 1 套冻结 demo 数据集。 |
| 时序 | 对 1 类检查项展示趋势、阈值、异常提示和复检建议。 |
| 视觉 | 对 1 个代表图片展示识别结果、置信度和表单联动。 |
| 质检 | 对 1-2 条巡检质检规则输出疑点和依据。 |
| 知识库 | 能命中标准、阈值、复检步骤或历史案例。 |
| Agent | 能生成复检清单、巡检摘要和交接班关注项。 |
| 人工确认 | 展示复检确认和归档状态，不触发真实派单审批。 |
| 追溯 | 关键结论能回到来源记录、命中规则或证据图片。 |

冻结后新增数据、新增规则、新增页面、新增接口、新增报表模板或新增模型调用，都应视为变更。

缺失样例、缺失规则或缺失证据时，应在演示准备阶段补齐，或在页面和报告中显式提示；不要静默生成默认结论。

## 9. 责任边界

必须和业务方确认一句话：

> 第一版 demo 的所有 AI 结论均用于演示和辅助判断，不直接作为正式考核、派单、审批、维保或审计依据。

责任边界：

| 边界项 | 第一版推荐 | 不建议第一版承诺 |
| --- | --- | --- |
| 风险提示 | 系统生成疑点、原因和复检建议 | 直接触发真实生产处置。 |
| 人员到位 | 展示迟到、漏填、异常未说明等疑点 | 自动写入正式绩效或考核系统。 |
| 复检建议 | 输出复检清单和依据 | 自动生成维修计划或强制执行。 |
| 报告归档 | 生成演示态报告和案例摘要 | 作为正式审计或生产记录。 |
| Agent | 生成巡检、复检、报告相关内容 | 自主操作系统、修改数据、自动审批。 |

## 10. 会上可以这样说

### 10.1 开场

```text
我理解你们现在已经有定期巡检、表单填写、人员到位监控和复检流程。
这次 demo 不是重做巡检系统，而是演示 AI 在这些节点上怎么提效。
我们建议围绕一条真实巡检记录来做：先展示任务和表单，再展示 AI 如何发现疑点、辅助复检、生成报告和归档。
```

### 10.2 解释视觉模型

```text
视觉模型不需要一开始替代全部人工巡检。
它更适合先从表单里“看得见”的检查项切入，比如仪表读数、阀位、指示灯、机柜灯态、外观泄漏和消防器材。
两周 demo 里可以选 1 个视觉检查项，做出识别框、标签、置信度和表单回填效果。
```

### 10.3 解释时序模型

```text
时序模型适合处理连续变化的参数，比如压力、差压、液位、温度、流量、电压电流。
demo 里不用训练复杂模型，可以用模拟曲线和轻量规则展示趋势偏移、阈值接近和异常提示。
关键是让业务方看到：AI 可以在巡检前或巡检中提示本轮重点复核点。
```

### 10.4 解释知识库和 Agent

```text
知识库的作用不是做百科问答，而是把巡检标准、阈值、复检步骤和历史案例归档起来。
当 AI 或人工发现疑点时，知识库能命中依据，Agent 能生成复检清单、巡检摘要、交接班关注项和报告。
```

### 10.5 引导拍板

```text
为了两周内做出稳定 demo，我们先只确认 6 件事：
主区域、视觉检查项、时序检查项、巡检质检点、知识库材料、Agent 输出。
这 6 件事定下来，demo 范围就能收住。
```

## 11. 后续路线

第一版 demo 跑通后，后续可以按阶段扩展：

```text
阶段 1：两周演示 demo
  固定样例数据
  AI 疑点发现
  知识库依据
  Agent 复检和报告
  人工确认和归档

阶段 2：半真实集成 demo
  接 1 个真实接口或真实模型
  使用脱敏真实数据
  完善规则和验收口径

阶段 3：试点 MVP
  接真实巡检系统或站场数据
  完善权限、审计、部署和联调
  进入试点业务验证

阶段 4：正式项目
  多站点、多设备、多规则
  真实消息 / 工单 / 审批闭环
  知识库和规则管理
  模型评测与迭代
```

当前定版结论：

```text
第一版先做一条能讲清楚的 AI 赋能巡检闭环，
不要把两周 demo 扩成巡检平台、系统集成项目或模型研发项目。
```
